# Backend API (этапы B–C)

Административный listener: `127.0.0.1:3001`. Mock listener: `127.0.0.1:4000`. Все команды выполняются из корня репозитория; сначала запустите `npm run dev` или `npm run build && npm start`.

## Первый проект через curl

Создать Shop API из готовой конфигурации, запустить и получить оба варианта ответа:

```sh
curl -i -X POST http://127.0.0.1:3001/api/projects \
  -H 'Content-Type: application/json' --data-binary @examples/shop.json
curl -i -X POST http://127.0.0.1:3001/api/projects/shop/start
curl -i http://127.0.0.1:4000/shop/api/products
curl -i 'http://127.0.0.1:4000/shop/api/products?mode=error'
curl -i -X POST http://127.0.0.1:3001/api/projects/shop/stop
```

Создание возвращает HTTP 201 и `{config, revision, state}`. Новый проект создаётся остановленным, даже если autoStart=true: автозапуск применяется при старте приложения. Повторное создание существующего ID или prefix возвращает 409. Остановка не изменяет autoStart. enabled=false запрещает запуск и останавливает уже работающий проект при сохранении.

Минимальный POST body: `{"id":"empty","name":"Empty API","prefix":"/empty"}`. Остальные поля получают безопасные defaults: basePath `/`, enabled=true, autoStart=false, пустые endpoints, CORS без credentials и JSON 404. Также можно передать полную конфигурацию, как в примере. Для строгого импорта полного документа используется POST `/api/projects/import`.

## Изменения и ревизии

GET проекта возвращает `revision` в JSON и в ETag. Для PATCH, PUT, DELETE проекта и всех изменений endpoints требуется `If-Match` с актуальной ревизией (с кавычками либо без). Отсутствующая ревизия — 428, устаревшая — 409. Ревизия — SHA-256 точных байтов файла. Ответы мутаций возвращают новый ProjectSnapshot; используйте его revision для следующего изменения.

```sh
curl -i http://127.0.0.1:3001/api/projects/shop
```

Скопируйте ETag из ответа вместо `REVISION`:

```sh
curl -i -X PATCH http://127.0.0.1:3001/api/projects/shop \
  -H 'Content-Type: application/json' -H 'If-Match: REVISION' \
  -d '{"name":"Shop API updated"}'
```

PATCH меняет только переданные поля; id/schemaVersion неизменяемы. Для изменения всего документа: PUT `/api/projects/shop/config` с JSON body и If-Match. GET того же маршрута возвращает конфигурацию без runtime-метаданных. Сохранение применяет маршруты без перезапуска listener; уже начавшийся запрос заканчивается на прежнем snapshot.

Записи приложения сериализуются и используют синхронизацию временного файла + rename. Создание использует атомарный link без замены существующего файла. При внешнем изменении файла запись с прежней ревизией отклоняется; Chokidar загружает внешнюю версию без перезапуска. Ревизия проверяется также непосредственно перед rename. Межпроцессная блокировка не реализуется: внешняя запись в узком промежутке между последней проверкой и rename всё ещё может конкурировать с сохранением. [Чтение версии с диска и явное разрешение конфликта](filesystem.md).

## Маршруты

| Метод | Путь | Результат |
| --- | --- | --- |
| GET | /api/health | Состояние admin listener |
| GET | /api/server/status | Адреса listener |
| GET / POST | /api/projects | Список snapshots / создание |
| GET / PATCH / DELETE | /api/projects/:id | Просмотр / изменение / удаление |
| POST | /api/projects/:id/duplicate | Новый проект с новыми ID и prefix, остановлен |
| GET / PUT | /api/projects/:id/config | Документ / замена документа |
| POST | /api/projects/:id/start | Запуск включённого проекта |
| POST | /api/projects/:id/stop | Остановка без изменения autoStart |
| GET / POST | /api/projects/:id/endpoints | Список / создание endpoint |
| PATCH / DELETE | /api/projects/:id/endpoints/:endpointId | Изменение / удаление endpoint |
| POST | /api/projects/:id/endpoints/:endpointId/duplicate | Копия с новыми ID, уникальным путём и enabled=false |
| GET | /api/project-diagnostics | Файлы, не загруженные при старте |
| POST | /api/projects/import | Строгий импорт полной конфигурации |
| GET | /api/projects/:id/export | Скачивание актуального валидного JSON с диска |
| GET | /api/projects/:id/disk | Текст файла, ревизия, ошибки и валидная конфигурация, если доступна |
| GET | /api/project-changes | instanceId процесса и версия реестра для опроса UI |

POST/PATCH endpoint принимают полный endpoint/частичные поля соответственно. Изменения endpoints возвращают snapshot проекта. DELETE проекта возвращает 204. Дублирование endpoint добавляет в начало пути сегмент `/copy-<id>`, чтобы копия не конфликтовала с исходным маршрутом. Измените её путь перед включением.

## Семантика mock engine

- Самый длинный prefix владеет запросом; проверяются границы сегментов. Остановленный вложенный проект не передаёт запрос родительскому.
- Статический путь приоритетнее `:param`, затем `*` в последнем сегменте. Составные и regex-параметры не поддерживаются. Метод задаётся явно, HEAD требует отдельного endpoint.
- Повторные и завершающие слеши нормализуются. Query не входит в matching пути, path params декодируются. Неверное кодирование — 400.
- Условия объединяются AND. Условные включённые варианты выбираются по priority по убыванию, затем по порядку в массиве. Default — только fallback, его условия не проверяются. Неусловный вариант без default также подходит всем запросам и участвует в приоритетах.
- Query/path/header сравнивают скаляры с их строковым представлением; repeated query представлен массивом, для проверки отдельного значения используйте contains. Body сохраняет JSON-типы и поддерживает dot notation и индексы массивов. equals для объектов/массивов использует структурное сравнение. Header names регистронезависимы.
- exists отличает отсутствующее поле от null. Отсутствующее поле соответствует только notExists; отрицательные сравнения по нему не срабатывают. contains работает для подстрок и элементов массива; in проверяет совпадение всего значения с элементом списка.
- Неизвестный проект: 404 PROJECT_NOT_FOUND; остановленный: 404 PROJECT_STOPPED. Неизвестный путь или метод внутри запущенного проекта: его notFound. Нет подходящего варианта и включённого default: 500 NO_RESPONSE_VARIANT.
- JSON отправляется корректно и для строк/чисел/null. Текстовые форматы отправляются строкой. HEAD, 204 и 304 не содержат body. Поле contentType имеет приоритет над заголовком Content-Type. Transport headers управляются сервером.
- fixed/random delay задаётся в миллисекундах до 60 000, random включает обе границы. Задержка не блокирует event loop.
- CORS применяется в пределах проекта. Явный OPTIONS endpoint имеет приоритет. Автоматический preflight проверяет origin, метод и запрошенные headers; запрещённый preflight — 403. У обычного запроса с запрещённым origin отсутствует разрешающий CORS-заголовок.
- Generated body пока возвращает 501 GENERATION_UNAVAILABLE; его выполнение относится к этапу E. Журнал запросов — к этапу F.

## Файлы и ошибки

JSON-файлы загружаются при старте из PROJECTS_DIR и отслеживаются Chokidar. Имя должно соответствовать id. Невалидные файлы, symlinks, слишком большие конфигурации и конфликты не мешают работе остальных проектов. Список актуальных проблем доступен в `/api/project-diagnostics`; ошибки схемы содержат JSON-path. Повторный prefix при старте обрабатывается детерминированно: файлы сортируются по имени, первый корректный загружается. При изменениях приоритет сохраняет уже принятая конфигурация; конфликтующий файл повторно проверяется после освобождения prefix.

API использует `{error:{code,message,issues?}}`; issues содержат JSON-path. Ошибки файловой системы возвращаются без путей и stack traces. MAX_BODY_SIZE ограничивает как HTTP body, так и размер проекта. Постоянное хранилище не содержит state, revision или request logs.
