# Интерфейс (этап D)

После `npm run dev` откройте http://127.0.0.1:5173. Production-интерфейс обслуживается административным сервером: `npm run build && npm start`, по умолчанию http://127.0.0.1:3001.

## Первый endpoint

1. Нажмите «Проект» или «Создать проект». Укажите название, безопасный ID, prefix `/shop` и base path `/api`.
2. Нажмите «Добавить endpoint». Настройте GET `/products`, название и JSON-тело во вкладке Response.
3. Сохраните документ кнопкой «Сохранить» или Ctrl/⌘ S. Затем нажмите «Запустить».
4. Внешний запрос `curl http://127.0.0.1:4000/shop/api/products` получит выбранный ответ.
5. Через кнопку `+` рядом с Response variant добавьте ответ 500. Во вкладке Rules добавьте query-условие `mode equals "error"`.
6. Сохраните изменения и вызовите `curl 'http://127.0.0.1:4000/shop/api/products?mode=error'`.

Изменения всех форм одного проекта объединены в общий черновик. Запуск разрешён после сохранения; ручная остановка доступна во время редактирования и не меняет autoStart. Если ввод продолжается во время сохранения, завершившийся запрос подтверждает только отправленную версию: более новые изменения сохраняются в черновике.

## Проекты и endpoints

Sidebar поддерживает поиск по названию проекта, методу, пути и названию endpoint; сворачивание, цветовые обозначения методов и runtime-состояния. Отключённые endpoints приглушены. Ширину sidebar можно менять мышью или стрелками на разделителе. На узком экране дерево открывается кнопкой меню.

В меню проекта доступны открытие, создание endpoint и копирование базового URL. На странице проекта отображаются endpoints и настройки: название, описание, prefix/basePath, enabled, autoStart, CORS и проектный 404. Дублирование, экспорт и удаление находятся в настройках. Удаление требует подтверждения. Для экспорта и дублирования сначала сохраните либо отмените изменения.

Endpoint Editor содержит Request, Response, Rules и Settings. Request показывает path-параметры и поля, используемые в условиях. В Settings доступны описание, enabled, дублирование и удаление. Новая копия получает новые ID, уникальный путь и enabled=false. Её нужно настроить, сохранить и включить. Полный URL использует адрес mock listener; рядом есть кнопка копирования.

## Ответы и правила

Варианты ответов можно создавать, дублировать, удалять, отключать и менять местами. Последний вариант не удаляется. Rules позволяет установить priority и единственный default. Все условия объединяются AND. Value вводится как JSON: строка `"error"`, число `42`, boolean `true`, список `["a", "b"]` для in. Операторы exists/notExists не требуют value.

Response поддерживает status, Content-Type, JSON headers, тело и fixed/random delay в миллисекундах. JSON, HTML, XML и plain text сохраняются в общей конфигурации. Неверные headers, синтаксис JSON и ошибки общей схемы показываются перед сохранением. Некорректный текст остаётся в черновике, а модель и preview используют последнюю корректную версию поля.

Preview показывает выбранный вариант, status, Content-Type, headers, задержку и тело. HEAD, 204 и 304 показываются без тела. Preview не выполняет mock-запрос и не угадывает условный вариант. В Generated-режиме кнопка Generate preview создаёт отдельный результат без записи конфигурации. [Настройка генерации по образцу](generator.md). Панель истории запросов относится к этапу F.

## JSON и внешние изменения

Переключатель JSON открывает весь проект в Monaco с локальными worker-файлами, проверкой синтаксиса и JSON Schema. Monaco подгружается по требованию, CDN не используется. Межполевые и межпроектные ограничения дополнительно проверяются общей Zod-схемой и backend. Невалидный полный документ нельзя открыть в визуальном режиме до исправления. Если отдельное JSON-поле формы невалидно, сначала исправьте его или отмените черновик.

«Форматировать» приводит документ к отступам в два пробела. «Отменить» возвращает актуальную серверную конфигурацию после подтверждения. При переходе в другой проект и закрытии вкладки несохранённые изменения защищены предупреждением. Переход между endpoints того же проекта сохраняет общий черновик.

При внешнем изменении чистый документ обновляется автоматически. Если есть несохранённые правки, показывается предупреждение, черновик остаётся нетронутым. Диалог конфликта показывает обе версии и предлагает:

- продолжить редактирование;
- загрузить версию с диска с подтверждением замены черновика;
- подтвердить сохранение собственного документа поверх просмотренной версии.

Перезапись использует актуальную disk revision. Если файл изменился ещё раз, требуется новое решение. Невалидную дисковую версию можно загрузить в JSON-редактор, исправить и сохранить через тот же механизм. Ошибки watcher видны над рабочей областью.

## Темы и проверка

Mantine сохраняет выбор светлой/тёмной темы локально; Monaco использует ту же тему. Конфигурации проектов хранятся в файлах backend, а не в localStorage.

React-тесты проверяют обновление чистого документа, сохранение dirty draft, конфликт невалидного файла, загрузку просмотренной версии, неизменность ID и ввод во время сохранения. В браузере проверены создание проекта/endpoint, Monaco body, условный HTTP 500, запуск, полный JSON, dirty navigation, внешний конфликт, темы и ширины 1280 и 390 px. Проверки реальных HTTP-ответов выполнялись отдельно от preview.

Редактор endpoint использует компактную шапку и общую строку настроек варианта. Статус, Content-Type и режим тела расположены над редактором; headers и задержка — рядом с ним на широком экране и ниже на телефоне. Response preview раскрывается под формой и прокручивается отдельно. Высота редактора тела подстраивается под высоту окна.
