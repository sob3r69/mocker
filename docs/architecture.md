# Архитектура и этапы

## Границы модулей

- `packages/shared/src/schemas`: единственная схема конфигурации, JSON Schema для Monaco, валидация и нормализация.
- `packages/shared/src/types`: DTO административного API; runtime registry в backend не экспортируется клиенту.
- `apps/server/src/admin`: административный Fastify listener, `/api`, frontend production.
- `apps/server/src/mock`: отдельный listener без административных маршрутов.
- `apps/server/src/config`: env, пути относительно корня репозитория.
- `apps/client/src`: React, Mantine, Router, TanStack Query и Axios.
- `examples`: проверяемые примеры; `data/projects`: пользовательские JSON-файлы.

## Контракт

MockProject содержит версию, безопасный ID, prefix, basePath, enabled, autoStart, CORS, notFound и endpoints. Endpoint содержит метод, путь и варианты. Вариант содержит стабильный ID, условия AND, приоритет и ответ. Все вложенные структуры строгие. ID уникальны внутри проекта, ID проектов и prefix уникальны в коллекции. Отсутствующие совместимые настройки получают defaults; неизвестные поля считаются ошибкой.

Состояние running/stopped/error и hash ревизии передаются в ProjectSnapshot, но не записываются в JSON. Каждое изменение конфигурации проходит общую схему и проверку коллекции. Сохранение выполняется через временный файл и rename; If-Match сравнивается с SHA-256 актуальных байтов файла внутри последовательной очереди записи. Chokidar обновляет immutable runtime snapshot только после полной проверки. Невалидная внешняя конфигурация оставляет последнюю рабочую версию и диагностическое состояние; удаление файла удаляет проект из runtime.

## Маршрутизация (этап B)

Выбрать самый длинный prefix по границе сегмента, проверить running и basePath, найти маршрут по методу через find-my-way. Поддерживаемый MVP синтаксис: статические сегменты, целый сегмент `:id`, завершающий `*`; регулярные выражения и составные параметры исключены. Статический маршрут приоритетнее параметризованного, параметризованный — wildcard. Имена параметров не отличают маршруты при проверке конфликтов. Query не входит в путь. Завершающие и повторные слеши нормализуются. Параметры декодируются matcher; неверное URL-кодирование возвращает 400.

Выбрать включённый условный вариант с максимальным priority, при равенстве — первый в массиве. Default проверяется только как fallback. Query/path сравниваются со строковым представлением скалярного значения условия, body — с сохранением JSON-типа; имена header регистронезависимы. Доступ к body использует только собственные безопасные свойства. Отсутствие fallback — диагностический 500. Остановленный/неизвестный проект — общий 404; неизвестный маршрут или метод активного проекта — project.notFound.

Явный OPTIONS endpoint имеет приоритет над автоматическим preflight. CORS применяется только к выбранному проекту. 204, 304 и HEAD не отправляют тело. Генерация не выполняет пользовательский код. Каждый запрос удерживает snapshot конфигурации до окончания задержки и отправки ответа.

## План

A. Собираемые workspaces, строгие общие схемы, JSON Schema, примеры, два listener, минимальная страница подключения.
B. Storage, CRUD и lifecycle; matcher, conditions, response engine, CORS, delays; unit и HTTP-тесты.
C. Atomic writes, watcher, import/export, ревизии и конфликты; тесты внешних изменений.
D. Shell, формы, endpoints/variants/rules, Monaco, dirty state, конфликт версий, preview.
E. Вывод схемы по примеру, Faker, ограничения, preview и runtime generation.
F. Ограниченный журнал с маскированием, фильтры, экспорт; административный SSE и панель логов.
G. Полная интеграционная проверка, Docker и руководство эксплуатации.

SSE допускается только для административных уведомлений. Mock SSE, WebSocket, proxy, встроенный HTTP-клиент и база данных исключены.

## Текущий результат

Этапы B–E реализованы. Контракты административного API, примеры curl и поведение runtime описаны в [Backend API](backend-api.md). Watcher, импорт/экспорт и разрешение файловых конфликтов описаны в [работе с файлами](filesystem.md). [Интерфейс](interface.md) использует общий документ с ревизией, отдельные буферы невалидного JSON и TanStack Query для серверных данных. [Генератор](generator.md) изолирован в backend: вывод схемы, preview и runtime используют общие контракты, а каждый вызов получает отдельный Faker. Следующий этап F — журнал запросов и его панель.
