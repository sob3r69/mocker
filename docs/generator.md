# Генерация данных по JSON-образцу (этап E)

## Интерфейс

Откройте endpoint → Response → «Генератор по JSON-образцу». Можно также выбрать Generated для ответа, у которого ещё нет схемы.

1. Вставьте JSON-пример. Поддерживаются скаляры, null, объекты, вложенные объекты и массивы.
2. При необходимости задайте количество элементов однородных массивов и seed.
3. Нажмите Generate preview. Справа появится результат; схему можно раскрыть в секции «Схема генерации».
4. Нажмите «Применить генератор»: образец, схема и режим Generated попадут в общий черновик проекта.
5. Нажмите «Сохранить» в редакторе проекта. После запуска endpoint будет генерировать тело на каждом HTTP-запросе.

Preview не записывает JSON, не меняет ревизию и не применяет настройки. После изменения образца, количества или seed предыдущий preview нельзя применить: сначала обновите его. Закрытие диалога без применения оставляет документ прежним.

В правом Response Preview кнопка Generate preview использует уже выбранную сохранённую или черновую схему. Это отдельный пример результата, не входящий запрос. Без seed он может отличаться от следующего HTTP-ответа.

Переключение в Static возвращает исходный образец из `body`; схема сохраняется и может быть включена снова. Настройка генератора не создаёт новый endpoint и не изменяет его conditions, headers или delay.

## Вывод схемы

Имена полей сопоставляются без учёта регистра, подчёркиваний и дефисов. Например, firstName, first_name и FIRST-NAME распознаются одинаково.

| Поле | Генерация |
| --- | --- |
| id: number | Положительное случайное число |
| id: string, uuid: string | UUID |
| name, firstName, lastName | Полное имя / имя / фамилия |
| email, phone | Email / телефон |
| city, country, address: string | Город / страна / улица с номером |
| date, createdAt, updatedAt | ISO-дата в фиксированном диапазоне 2020–2030 |
| price, amount: number | Число; целочисленность образца сохраняется |
| title, description | Предложение / несколько предложений |
| url, avatar | Строка URL |
| Неизвестное string-поле | Несколько случайных слов |
| Неизвестное number-поле | Случайное число с сохранением целочисленности |
| boolean, null | Случайный boolean / неизменный null |

Тип имеет приоритет над именем: числовой name остаётся числом, строковый price — строкой. Объект address сохраняет вложенную структуру; он не заменяется строкой адреса. Связи между полями не выводятся: createdAt/updatedAt и city/country генерируются независимо.

Однородные массивы используют схему элемента и count. Заданное пользователем количество применяется ко всем непустым однородным массивам, включая вложенные. Без override сохраняются размеры образца. Пустые массивы остаются пустыми: тип элемента неизвестен. Разные формы и типы элементов сохраняются в узле tuple, без замены всех элементов первым образцом; длина такого массива фиксирована.

## Хранимый JSON

```json
{
  "status": 200,
  "contentType": "application/json",
  "headers": {},
  "body": [{ "id": 1, "email": "sample@example.com" }],
  "delay": { "type": "fixed", "value": 0 },
  "bodyMode": "generated",
  "generation": {
    "schema": {
      "type": "array",
      "count": 3,
      "items": {
        "type": "object",
        "properties": {
          "id": { "type": "value", "generator": "id", "integer": true },
          "email": { "type": "value", "generator": "email" }
        }
      }
    },
    "seed": 42
  }
}
```

Схема состоит из value, object, array и tuple. value содержит generator из фиксированного списка; необязательный integer задаёт числовой режим. tuple содержит массив схем items. Неизвестные поля и генераторы отклоняются. Старые схемы value/object/array без integer продолжают работать. Функции и JavaScript из конфигурации не выполняются.

Без seed создаются новые данные при каждом запросе. С seed, включая 0, одинаковая схема даёт одинаковый результат независимо от других запросов и preview. Для каждого вызова создаётся отдельный Faker с locale en; глобальное состояние randomizer не используется. Диапазон дат фиксирован, поэтому дата запуска не влияет на seeded output. Обновление версии Faker может изменить значения при том же seed.

## API и пример

POST `/api/generator/infer` принимает `{example, arrayCount?, seed?}` и возвращает `{generation}`. POST `/api/generator/preview` принимает generation целиком и возвращает `{generation, body}`. Оба маршрута находятся только на административном listener.

```sh
curl -s http://127.0.0.1:3001/api/generator/infer \
  -H 'Content-Type: application/json' \
  -d '{"example":[{"id":1,"email":"sample@example.com"}],"arrayCount":3,"seed":42}'

curl -s http://127.0.0.1:3001/api/generator/preview \
  -H 'Content-Type: application/json' \
  -d '{"schema":{"type":"value","generator":"email"},"seed":42}'
```

Готовый проект: [examples/generated.json](../examples/generated.json).

```sh
curl -i -X POST http://127.0.0.1:3001/api/projects/import \
  -H 'Content-Type: application/json' --data-binary @examples/generated.json
curl -i -X POST http://127.0.0.1:3001/api/projects/generated/start
curl -s http://127.0.0.1:4000/generated/api/users
```

## Ограничения

- Максимальная глубина генерации — 10 от корня образца.
- Размер одного массива — до 1000 элементов.
- Общий размер развёрнутой структуры — до 10 000 узлов, включая вложенные массивы.
- Сериализованное тело — до 1 МиБ. Размер учитывается по ходу генерации, включая ключи и UTF-8.
- MAX_BODY_SIZE дополнительно ограничивает запросы анализа/preview и файлы проекта.
- До рекурсивной валидации административный JSON ограничивается глубиной 64 и 100 000 узлами. Ключи __proto__, constructor и prototype запрещены; файлы проходят ту же проверку.

Ошибки схемы содержат JSON-path. Превышение лимита результата возвращает 422 GENERATION_LIMIT; неверные параметры — 400. HEAD, 204 и 304 не создают и не отправляют body, даже в Generated-режиме. Runtime, импорт, файловый watcher и JSON-редактор используют одну общую Zod-схему.

Unit/HTTP-тесты проверяют типы, семантические имена, вложенность, массивы, seed, лимиты, отсутствие записи при preview, сохранение схемы и совместимость с conditions. React-тесты проверяют явное применение и защиту от устаревшего preview. `npm run test:smoke` дополнительно проверяет генерацию и восстановление seeded output после перезапуска через настоящие TCP-порты.
